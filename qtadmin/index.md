# 先集中，后分化，再连接

功能堆叠是组织演化的必经阶段。一个容器先吸收所有功能，领域分化后再迁出，最终只保留交叉编排。

## 三个阶段

- 集中期：领域信息不足，功能堆在最近的入口，用广度试探深度
- 分化期：领域形成自己的容器，功能开始迁出
- 连接期：中心容器只保留跨领域编排，平台承载并行战略的编排，不是功能堆叠

停止堆功能的判据：领域有了自己的容器，且堆功能的边际成本开始超过收益。

## 实现位置

qtadmin 已走完分化：业务域全部归位各平台仓库，CLI 收敛为五个职能域命令。asset 已落地，delib 与 strategy 仍零实现；连接期的交叉编排（产教融合、strategy 载体）尚未达到。

## 基础能力

- 职能域下沉领域层：human、asset、connect 的规则沉淀到领域档案与规格层，CLI 只做执行
- 数据契约：恢复 Provider 演进，字段与档案同源
- 封装边界：AI 产出必须可落地；知识以状态区分（settled / evolving / draft）
- 演进方向：优惠券和代金券是未来代币的前身；不靠堆人，靠系统

## 边界

- 分化未完成时强行拆分，功能无处安放
- 交叉点不靠人为强推，分化充分后自然涌现
- 同一规律作用于人：身兼两职是人的集中期
