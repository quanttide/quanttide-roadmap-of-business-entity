# 量潮课堂产品路线图

量潮课堂分两段推进：**v0.1 固定一版数据模型，v1.0 实现商业化运营**。模型是全线最难的事情，也是本阶段唯一的硬指标；服务端在模型定型前刻意不动。

## v0.1 —— 固定一版数据模型（当前阶段）

v0.1 系列以静态网页为主：展示、招生、练习各面先以静态形态充当探针。服务端不作超前设计——模型未定就写服务端，等于把没想清楚的东西浇成混凝土。

本阶段交付的是**一版可执行的数据模型契约**，不是一版服务端代码。做法是把学习管理这套新范式的核心概念写成契约，用真场景反复喂：任务怎么指派、怎么验收，课程怎么排布，考核怎么记录——喂饱了还站得住，才叫固定。契约定型之后，服务端是照契约浇筑，「不敢设计」变成「照图施工」。

模型收敛的三条判断：

- **模板与实例的分野是第一刀**。内容模板被指派才产生实例；状态、评语、判定、付费解锁全是实例侧的事件，挂在实例上而不是模板上。这一刀下去，其余概念挂哪边自动确定。
- **模型不是从零看清，是看清一半**。静态阶段已落两笔真模型：任务的两把尺（需求的精确程度、验收标准的开放程度）与五状态机。本阶段把已露头的实体收敛成少数几个中心概念，其余降为属性或事件——选多了模型散，选少了塞不下。
- **理论与实践分属两个引擎**。理论课以 qtcloud-course 为引擎，管顺序与门槛：课程、模块、课时，过门槛解锁；实践课以 qtcloud-learn 为引擎，管验收回路：提交、判定、通过或退回、评语。两套回路不共用心脏；当前两引擎仓在、服务未醒，随模型固定依次接通。

v0.1 的收口顺序：数据模型契约喂稳 → 服务端照契约落地 → 两个引擎接通各面 → 实训旅程（报名、问卷、领任务、交付、评审、入册）由人工驱动转为产品化（0.2.0）→ C 端付费闭环 → 接口冻结。

## v1.0 —— 商业化运营

标志三条，缺一不发：

1. **API 稳定**：契约即接口，模型固定之后接口不再发生破坏性变更。
2. **付费功能完整**：C 端课时包与代金券走完整在线闭环——钱包与订单已有家底，欠的是接上；G、B 端维持询价洽谈，不走在线支付。
3. **可商业化运营**：招生、交付、验收、回款全链路在引擎上跑通，不再依赖人工驱动。

## 共同原则

1. **规则不写入代码**：准入门槛、评审标准、代金券规则由实训基地自主决定。产品只提供配置界面、记录每次变更并归档，不假设自己是唯一流程载体——规则固化进版本，基地每修订一次规则就要发一次版，产品由此收回已交付的决定权。
2. **数据结构先于界面生成**：先固化旅程状态、门槛配置、任务定义，再生成界面与接口。反之各端独立实现将迅速偏离——课程系统、实训系统、数据面三处已出现此迹象。
