# 量潮课堂产品路线图

量潮课堂按角色分三端，产品面按 scope 分篇维护：

| Scope | 产品面 | 路线图 |
|-------|--------|--------|
| site | 展示与招生：课程体系、价格、报名 | [site.md](site.md) |
| studio | 教学与客户面：派任务、批改、客户看交付 | [studio.md](studio.md) |
| lite | 学员面：任务系统，课程与实训都是任务序列 | [lite.md](lite.md) |
| provider | 数据面：任务模型、状态表、回写通道 | [provider.md](provider.md) |
| cli | 命令面：骨架 | [cli.md](cli.md) |

实训旅程（报名、问卷、领任务、交付、评审、入册）目前以文档与实验室工作台人工驱动，0.2.0 产品化进任务系统，与既有课程内容并列，互不侵入。

## 共同原则

1. **规则不写入代码**：准入门槛、评审标准、代金券规则由实训基地自主决定。产品只提供配置界面、记录每次变更并归档，不假设自己是唯一流程载体——规则固化进版本，基地每修订一次规则就要发一次版，产品由此收回已交付的决定权。
2. **数据结构先于界面生成**：先固化旅程状态、门槛配置、任务定义，再生成界面与接口。反之各端独立实现将迅速偏离——课程系统、实训系统、Provider 三处已出现此迹象。
