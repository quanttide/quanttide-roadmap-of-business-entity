## 待办

### v0.2 任务链路（应用侧的全部数据面）

播放器降级为任务管理系统后，「studio 派任务 → lite 取任务 → 交付 → 回写」经本服务即全部：

- [ ] 任务下发：studio 派发（班级 / 学员、截止、验收标准）→ lite 拉取（按 learner 投影今日任务卡）
- [ ] 交付提交：lite 提交交付物 → studio 批改面收取
- [ ] 任务状态回写：派发 / 提交 / 退回重做 / 通过
- [ ] 单元并入任务：反馈单元不另立实体——课程 = 任务序列，任务 = 小需求 + 动作 + 判定 + 反馈；每任务挂一条 criterion 回写完成记录
- [ ] 任务书与任务实例分离：任务书是仓内版本化内容（学员修订 → 教师合稿 → 版本回灌，修订是分叉、合稿是裁决），任务实例是派发记录——内容与账分面，修订不改实例，回灌不丢轨迹
- [ ] 状态表即流程定义：状态迁移逐个接口守卫，不允许绕过

### 数据模型约束

以下已在真实业务中发生，数据模型若无法承载，业务即无法进入系统：

- 任务须可关联订单来源——真实客户需求拆解为入门题分派，培养出口与接单能力挂钩
- 交付前须经不同机器、不同系统验证，不以作者自评为准
- 报名为周期性意愿确认，而非一次性投递
- 须记录行动与其效果的对应关系——运营、商务类岗位无实物产出，唯有此类记录使成果可见

### 云回归（回灌）

- 触发条件：课程云 / 学习云模型稳定，且出现第二个消费者（训练营独立售卖、企业培训接入）
- 回灌范围：仓内内容迁回课程云，账本迁回学习云，任务模型对齐新契约；回归缝即客户端契约不变，应用侧零改动
- 仓内期间的缓存纪律：仓内数据是缓存不是事实源——带出处、可由上游重建；回灌时以云为准
- 学习云起步路径（回归后）：整合内容生产工具链 → HTML 教学原型试效果 → 蓝图试效果 → 基础数据就绪后链路跑通
