# studio 产品路线图

工作室是**教学设计工作台**：单用户（你作为老师），设计**大作业与它的解体思路**——题目、参考答案、步骤单元、脚手架、任务书生产线。无学员面、无客户面：学员的一切在 lite，交付数据的客户视角待有真实客户时再议。

## 核心判断：本体是 v0.1 的互动编排引擎

studio 的资产是**互动引擎**——节点带交互与选择的编排模型。当前任务系统的节点上**暂时装的是文档**（任务书、题面），不是视频；视频只是载荷之一，**换载荷不动模型**。创作空间的对象都长在这套节点载荷上，三件孪生同形（`id`(uuid) / `title` / `content`）：**Assignment 是题目，Solution 是参考答案，SolutionStep 是答案下的一层单元**（`after` 前置边组成 DAG）——studio 要做的，就是大作业的解体思路。

## 教学创作空间（优先方向，源自洞察仓 studio.md）

**新思路优先**：主方向不是"功能更多的工作台"，而是把隐性教学经验显性化的创作空间——装教学思路本身：为什么这个任务要这么拆、每一步的判断标准是什么、做到什么程度算过关、卡住时往哪想。

- [ ] Assignment（大作业）：数据契约三字段——`id`（uuid）/ `title` / `content`；content 当前装 Markdown 长文本（任务书全文），未来拓展视频等格式；解体与步骤按 id 配对。类落 `quanttide-tech-toolkit` 的 `dart/course`（BLoC 架构），studio 引包接入
- [ ] Solution（参考答案）：三字段孪生，content 装范例交付与正例反例对照——把及格线具象化；定框**参考答案不是标准答案**（与「自由发挥 + 陌生人检验」验收兼容），可选、一作业一档；类已落 toolkit 同仓
- [ ] SolutionStep（步骤单元）：Solution 下**一层不嵌套**的单元，三字段 + `after`（前置边）组成 DAG——投影即 lite 的过门槛（完成前置解锁本步）；判断标准、检查点、"老师为什么这么安排"全部写进 content，单元自足（注解不设模型）。模型已落 `quanttide-tech-toolkit` 的 `dart/course`
- [ ] 脚手架库：前置思考题、常见坑点、反思触发器——跨大作业复用的教学经验组件（示例反例位由 Solution 承接）
- [ ] 修订回环（任务书生产线）：新序列首任务 = 任务书修订；AI 预筛 diff，教师合稿回灌仓内任务书、按修订重排任务序列——教研嵌在任务流里，不设独立仪式

不做：权限 / 多人协作、AI 生成任务（先手写 2-3 个完整模板）、可视化拖拽（结构化表单 + Markdown 区块够用）。

落地顺序：**本方向与现场执行是同一条生产线，不设先后门槛**——修订回环就是把题目与步骤单元磨出来的第一块砖（任务书修订即最小编创）。

## 退场清单（2026-11-02 精简）

学员交互与客户面功能整体退场：派任务 / 批改、任务流预览（课堂投影）、客户面只读、规则配置（运营非设计）、学员侧收敛、淘汰赛、评审复盘流。

理由：studio 目前唯一使用者是设计者本人——为不存在的使用者做界面是把工程花在假设上；学员交互已有归宿（lite），客户消费的是数据不是界面；退场不产生用户损失，开班或接客时按届时需要回补，lite 与 provider 的接口缝不变。
