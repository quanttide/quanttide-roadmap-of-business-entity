# studio 产品路线图

工作室是服务方与客户的操作端。服务方面（教师 / 管理者）：派任务、盯进度、批改、合稿、排课、跑淘汰赛；客户面（学校、企业、付费个人）：看名下进度、核课时、收教研记录、对合同交付——v0.2 客户面极简只读。

## 教学创作空间（优先方向，源自洞察仓 studio.md）

**新思路优先**：studio 的主方向不是"功能更多的工作台"，而是把隐性教学经验显性化的创作空间——装教学思路本身：为什么这个任务要这么拆、每一步的判断标准是什么、做到什么程度算过关、卡住时往哪想。

- [ ] Brief：任务书结构化——对象 / 真实场景（晋江发行、4399 上线）/ 期望产出物 / 关联官网知识点
- [ ] 分解树：阶段 → 动作 → 检查点，每个动作带可核对的判断标准（不是"写完"，是"开头 300 字内有明确冲突"），检查点同步 lite
- [ ] 脚手架库：前置思考题、常见坑点、示例反例、反思触发器——把教学经验固化成可复用组件
- [ ] 教学动作元数据：每步挂"老师为什么这么安排"，学员在 lite 上可点开
- [ ] 评审复盘流：学员提交 → 预设维度评审表 → 复盘沉淀作品集 → 回流成下一批人的示例

不做：权限 / 多人协作、AI 生成任务（先手写 2-3 个完整模板）、可视化拖拽（结构化表单 + Markdown 区块够用）。

落地顺序：**本方向与下方现场待办是同一条生产线，不设先后门槛**——修订回环就是 Brief 与分解树的第一块砖（任务书修订即最小编创），现场待办按此方向执行、对象随线补充。

## 现场待办（v0.2 执行清单）

- [ ] 任务派发与批改：面向班级 / 学员，带截止与验收标准；评语、退回重做、通过
- [ ] 任务流预览：教师发布前过一遍任务列表与题面（含嵌入媒体），课堂现场直接投影任务
- [ ] 修订回环（教研生产线）：新序列首任务 = 任务书修订；AI 预筛 diff（哪几处被标不清楚），教师合稿回灌仓内任务书、按修订重排任务序列——教研嵌在任务流里，不设独立仪式
- [ ] 客户面只读投影：学校 / 企业 / 付费个人看名下进度、课时账、教研记录；付费个人可确认方案。不新增子系统，现有数据的客户视角
- [ ] 规则配置界面：承载门槛参数、问卷题目、评审结论、代金券规则，记录变更并归档（规则本身不写入代码，见[总则](index.md)）
- [ ] 学员侧收敛：登录、学习入口冻结待 lite v0.1 后定去留；播放器编排架构废弃，题面媒体组件保留
- [ ] 淘汰赛（v0.3）：班级进度视图（谁推进、谁掉队）、淘汰流程（触发、记录、通知）
