# studio 产品路线图

工作室是**教学设计工作台**：单用户（你作为老师），设计教学方案——互动节点（对象 / 分解 / 判断标准）、脚手架、教学动作、任务书生产线。无学员面、无客户面：学员的一切在 lite，交付数据的客户视角待有真实客户时再议。

## 核心判断：本体是 v0.1 的互动编排引擎

studio 的资产是**互动引擎**——节点带交互与选择的编排模型。当前任务系统的节点上**暂时装的是文档**（任务书、题面），不是视频；视频只是载荷之一，**换载荷不动模型**。创作空间的每个对象都长在这套节点模型上：Brief 是节点的定义，分解树是节点的序列，教学动作是节点的注解。

## 教学创作空间（优先方向，源自洞察仓 studio.md）

**新思路优先**：主方向不是"功能更多的工作台"，而是把隐性教学经验显性化的创作空间——装教学思路本身：为什么这个任务要这么拆、每一步的判断标准是什么、做到什么程度算过关、卡住时往哪想。

- [ ] Brief：任务书结构化——对象 / 真实场景（晋江发行、4399 上线）/ 期望产出物 / 关联官网知识点
- [ ] 分解树：阶段 → 动作 → 检查点，每个动作带可核对的判断标准（不是"写完"，是"开头 300 字内有明确冲突"），检查点同步 lite；设计态预览并入本视图
- [ ] 脚手架库：前置思考题、常见坑点、示例反例、反思触发器——把教学经验固化成可复用组件
- [ ] 教学动作元数据：每步挂"老师为什么这么安排"，学员在 lite 上可点开
- [ ] 修订回环（任务书生产线）：新序列首任务 = 任务书修订；AI 预筛 diff，教师合稿回灌仓内任务书、按修订重排任务序列——教研嵌在任务流里，不设独立仪式

不做：权限 / 多人协作、AI 生成任务（先手写 2-3 个完整模板）、可视化拖拽（结构化表单 + Markdown 区块够用）。

落地顺序：**本方向与现场执行是同一条生产线，不设先后门槛**——修订回环就是 Brief 与分解树的第一块砖（任务书修订即最小编创）。

## 退场清单（2026-11-02 精简）

学员交互与客户面功能整体退场：派任务 / 批改、任务流预览（课堂投影）、客户面只读、规则配置（运营非设计）、学员侧收敛、淘汰赛、评审复盘流。

理由：studio 目前唯一使用者是设计者本人——为不存在的使用者做界面是把工程花在假设上；学员交互已有归宿（lite），客户消费的是数据不是界面；退场不产生用户损失，开班或接客时按届时需要回补，lite 与 provider 的接口缝不变。
