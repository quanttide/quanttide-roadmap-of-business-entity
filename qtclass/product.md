# 量潮课堂产品路线图

当前主线：qtclass studio 升级 0.2.0，将学习系统与现有课程系统并列整合。

## 背景

studio 现有课程系统承载内容学习（浏览课程 → 播放 → 进度 → 立项）；实训旅程（报名 → 问卷 → 领任务 → 交付 → 评审 → 入册）已在实验室工作台完成河床参考实现，免费学员资格获取流程与付费培养流程已在手册定型。0.2.0 把学习系统作为独立子系统与课程系统并列，学员端形成「课程 + 实训」双入口。

## 架构

```
Studio (Flutter 0.2.0)                     Provider (Go)
┌─────────────────────────┐               ┌──────────────────────────┐
│ 课程系统（现有，不动）      │               │ course：课程数据（现有）     │
│  首页/列表/播放/立项       │               │ learn：学习云代理（现有）    │
│─────────────────────────│               │──────────────────────────│
│ 实训系统（新增）           │───API───▶     │ 旅程状态机 + 持久化（新增）  │
│  旅程时间线 + 节点动作面板  │               │                            │
└─────────────────────────┘               └──────────────────────────┘
```

- 状态迁移全部是系统内事件：每个迁移 = 一个接口，服务端守卫
- 状态机即数据：状态表即流程定义，改流程 = 改表，界面自动跟随
- 学员身份绑定 studio 登录账号，姓名仅作显示

## Studio 端

- 顶层导航并列：课程（现有全部不动）｜实训（新增），两系统互不侵入
- 新增旅程页（旅程时间线 + 当前节点动作面板，平移实验室工作台的信息架构）、问卷页（五道动机题、必填校验）、任务页、交付页
- 评审状态在旅程面板只读展示（通过/打回附原因）
- 评审录入（初审/终审、打回附原因）属课堂运营侧，管理界面不在本期

## 里程碑

1. M1 服务端旅程域：状态机迁移 + 持久化 + 接口 + 测试（全旅程迁移链、守卫、留痕）——约占四成，正确性核心
2. M2 studio 实训骨架：导航并列 + 旅程页（时间线/报名/问卷）接服务端 + 测试——约三成
3. M3 任务与交付：任务页/交付页接通 + 评审只读——约一成半
4. M4 发布：provider 0.2.0 → studio 0.2.0 走发布流程，主仓库指针同步——约一成半

## 版本

- provider：v0.2.0-alpha.1 → v0.2.0（新增旅程域与持久化）
- studio：v0.2.0（新子系统并列整合，minor 升级）
- site / root：不动；site 学习页为公开内容，与学员端旅程互补
