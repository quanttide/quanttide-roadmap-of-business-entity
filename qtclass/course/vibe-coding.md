# 氛围编程课程路线图

> 本文件记录氛围编程课程的设计演进。每次实践课后，根据学生反馈和评审经验更新。

## 实践课时1 概况

- **来源**：`data/profile/qtclass/course/vibe-coding/practice1.md`
- **任务结构**：熟悉结构 → 整理意图 → 整理洞察 → 更新路线图
- **激励模型**：无硬截止日期，自愿限时挑战 + 代金券激励

---

## 附加题（实践课时1）

> 下列附加题从教学方案设计本身中提取改进点，供有余力的学生选择挑战。完成附加题可获得额外激励（冲刺档代金券）。

### A1. 交付标准定义

当前任务1-4缺少明确的"完成标准"，容易导致投入度失控或产出参差。

**要求**：为实践课时1的四个任务分别定义两档交付标准：

- **标准档（最低可接受）**：满足什么条件即算任务完成？
- **优秀档（有亮点）**：满足什么条件超出预期？

每档写 2-4 条可验证的验收条件（如"至少提 1 个 issue + 1 个 PR"、"整理了至少 5 条意图"）。提交方式：在 `practice1.md` 末尾增加"交付标准"章节并提交 PR。

**挑战评级**：⭐⭐ 中等
**代金券加成**：冲刺档

---

### A2. 评审检查清单设计

任务1的 issue/PR 评审目前缺少标准化流程，评审人主观判断权重大，学生不知道自己是否"过关"。

**要求**：为实践课时1设计一份 PR 评审检查清单（checklist），包含：

1. **格式检查**：Conventional Commit？文件路径规范？
2. **内容检查**：issue 是否有根因分析？PR 是否引用关联 issue？
3. **质量检查**：文档语言是否通顺？结构是否合理？
4. **一票否决项**：什么情况下 PR 直接打回？

提交方式：在仓库 `.github/` 下新增 `PULL_REQUEST_TEMPLATE.md` 或 `review-checklist.md`，并提交 PR。

**挑战评级**：⭐⭐⭐ 较高
**代金券加成**：冲刺档 × 1.5

---

### A3. 激励方案设计

"无硬截止日期 + 自愿限时挑战 + 代金券"的三角激励模型已在方案中明确，但对以下细节尚未定义：

- 代金券面额和发放规则
- 标准档和冲刺档的时间窗口
- 多期课时之间的累计激励规则

**要求**：设计一份完整的激励方案文档，涵盖上述内容。尤其需要考虑：

- 激励如何与"敏捷故事点"联动？
- 学生如果在多个课时持续产出，奖励如何阶梯式增长？
- 如何避免"为奖励而凑 PR"的激励扭曲？

提交方式：在 `data/roadmap/qtclass/course/` 下新增 `incentive.md` 并提交 PR。

**挑战评级**：⭐⭐⭐⭐ 高
**代金券加成**：冲刺档 × 2

---

### A4. 文档自身改进

实践课时1任务书（`practice1.md`）本身也有可改进之处，真实体验"新人对文档提改进意见"的全流程。

> 提示：文中有一处常见笔误，可尝试找出来。

**要求**：至少提出 2 个文档改进点（含笔误修复），通过 issue 提交想法，通过后 PR 实现。改进点可以是：文字修正、结构重构、信息补充、示例添加等。

**挑战评级**：⭐ 入门
**代金券加成**：标准档

---

### 附加题提交规则

1. 附加题无截止日期，但越早提交越有机会获得额外激励
2. 冲刺档代金券需要附带附加题才能解锁（仅做标准档四个任务无法获得冲刺档激励）
3. 多做多个附加题，取最高档位发放，不叠加
4. 附加题同样遵循 issue → PR → 评审 → 合并的标准协作流程
