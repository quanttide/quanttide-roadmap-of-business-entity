# 量潮云路线图

量潮云是承载工作的生产平台，统一目标是消除人机协作摩擦。平台能否立住，不取决于单个功能，而取决于下列支持系统是否建成。

## 需要做的支持系统

- 数据工程：把飞书与 GitHub 两个源头的散落数据，建成按领域划分、可计算、可回流的数据云
- 账号与支付：零信任账号体系与代金券机制，两者是学员旅程连续化的两个卡点
- 协作目录与任务协议：执行者注册与事件契约，各云之间靠协议衔接，不靠代码依赖
- 状态机引擎：任务状态由规则推进，人只在验收闸门出现
- 工作台：承载旅程时间线与节点动作，取代人工对账
- 执行端点：各云接入任务协议，使流程真正连续
- 治理可视化：治理方法的系统化展示与执行，而非功能展示

## 验收标准

支持系统不以功能数量计，以真实业务场景走通为准。当前两场：报名到领任务在站内连续完成，旧系统逐段降级为异常通道；任务输入经多模块接力后交付并入档。场景之外的愿望列入外围，不进交付。

## 原则

- 连续优先于完备：先把河修连续，再修断片内部
- 按领域划分数据存储，不按基础设施供应商划分
- 内部先用：量潮自己的工作流优先，集成靠任务协议，不靠代码依赖
