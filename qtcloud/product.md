# 量潮云产品研发路线图

统一目标：帮助人类消除人机协作摩擦的第二大脑。

## 定位

量潮云是一个工作平台（Workbench）：承载工作的软件系统。用户与各云在同一套工作语言里协作——自然语言派活，任务拆解成流程，系统交付可验收成果。形态对标 CoWork/WorkBuddy，底层是自己的云。

## 概念基座

通用语言由工程标准定义（`quanttide-specification-of-business-entity/work/index.md`）：

| 概念 | 定义 |
|:-----|:-----|
| 工作平台 Workbench | 承载工作的软件系统 |
| 工作空间 Workspace | 围绕一个上下文组织工作的容器，空间之间相互独立 |
| 任务 Task | 工作的最小单元，有执行者与完成判定 |
| 工作流 Workflow | 任务按依赖编排成有向无环图（DAG） |

概念直接落为契约（workspace / task / workflow 最小 schema），各端读契约不读文档。执行者与交付物是下一组入册概念，随协作目录落地补充。

## 验收场景

招聘政策案例是唯一整体验收场景：任务输入 → 拆解为流程 DAG → 派活（多模块接力）→ 交付草案 → 验收。闭环跑通即产品成立，量潮自己的工作流是第一个 Workspace。交付范围以案例所需为限，不做案例之外的平台功能。

## 交付顺序

内部依赖序，全部并行开工、按此合入：

1. 概念契约：workspace / task / workflow schema
2. 协作目录：执行者注册与事件契约模型
3. Studio 工作台：空间创建 → DAG 拆解 → 派活 → 执行 → 验收
4. 执行端点：数据云、议事云接入任务协议
5. 端到端闭环：招聘政策案例跑通

## 版本

一次性发布 studio/v1.0.0：CoWork 完整形态 + 招聘政策案例闭环验收。门户由 site/v0.1.x 承载，已就位。

## 外围（随业务演进，不阻塞交付）

- 专家资产化：各云沉淀 SOP 与知识库，企业专属专家，按量交付
- 项目空间：多 Workspace 协作（外层 DAG）、流程沉淀复用——待空间模型内部验证后解禁
- 云业务扩张、双引擎（增长与管理）、招聘投递进社区、客服云

## 原则

- 从做对的系统到做活的系统
- 概念即契约：先定义通用语言，再写实现代码
- 内部先用：量潮自己的工作流优先，集成靠任务协议不靠代码依赖
- 范围以验收场景为限：案例之外的愿望进外围清单，不进交付
- 云体系的精密是系统级别的精密，不是单个功能的精密
- 用外部视角检验：开源结构加不断发布招聘，把项目融入其中
- 增长飞轮精密复杂，一言不合就可能会崩溃
