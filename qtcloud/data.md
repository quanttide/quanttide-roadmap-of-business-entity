# 量潮云数据工程路线图

数据工程是量潮云形态演化的配套底座：各云的任务执行、模块接力、专家知识沉淀都需要数据基础设施支撑。

现状：公司数据集中在两个源头——飞书（聊天记录、文档、招聘邮箱、人事流程）与 GitHub（代码、issue、PR、release、工作档案库）。数据工程的目标是把这两个源头的散落数据，建成按领域划分、可计算、可回流的数据云。

## 近期（形态 0.1 配套）

- 数据源盘点与资产化：盘点飞书与 GitHub 的数据源，按领域划分存储（数据工程、项目管理、商务拓展、资产管理），不按基础设施供应商划分
- 飞书数据导出管线：聊天记录、文档、招聘数据的导出与结构化，招聘子系统已验证导出到自有系统做二次分析的路径
- 数据蓝图：用 CUE 定义数据蓝图与 schema，把模糊文档变成可计算的框架
- 数据云 CLI 发布 MVP，落地数据集管理雏形
- 工作档案库 Git 化作为事实源，与飞书数据形成对照

## 中期（形态 0.2 到 0.3 配套）

- 模块接力数据流产品化：沟通模块取聊天记录、知识工程模块抽取加工、人事模块形成政策，跑通数据在各云之间的流转
- 数据集与数据应用管理：数据云核心特性落地
- 高质量小样本积累：公司日常数据标记与清洗，形成可复现过往的数据资产
- 研发流程数据治理：GitHub issue、PR、release 的审计与治理，支撑发布审计与规范检查

## 远期（形态 0.4 到 1.0 配套）

- 数据处理程序管理与流程编排，数据工程平台化
- 数据安全治理：权限最小化、脱敏与合规（客户数据内外一体流转的安全区）
- 专家生态的数据基础：SOP 与知识库结构化，支撑各云沉淀为领域专家

## 原则

- 按领域划分存储，不按基础设施供应商划分
- 先导出后分析：数据进自有系统再做二次分析，保证稳定性
- 高质量小样本优于海量数据：公司每一件事都认真做，资料稍加整理即可作为训练数据
- 复现过往：复现得越多，平台越成熟，未来就会重复
- Git 作为事实源，飞书数据回流档案库形成闭环
